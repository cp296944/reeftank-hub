# 2026-10-02 可靠性修正

狀態：本機修改與驗證；尚未發布 Release，也未部署至 Raspberry Pi。

## 使用者可見修正

- 資料庫開啟或遷移失敗會停止並保留原始檔，不再自動換成空庫。
- SQLite 匯出使用完整快照，包含已提交但尚未 checkpoint 的 WAL 資料。
- 內建水質資料改為一次性交易匯入；舊資料庫保留刪除結果，包括曾刪除全部紀錄的情況。
- 自動與手動 OTA 共用互斥保護。新版確認前檢查本機 HTTP、核心資料表與可寫性；HA、雲端或無線設備暫時離線不影響確認。
- 設備配對和水質儲存遇到斷線／逾時會解除按鈕鎖定、保留輸入；不自動重送可能已成功的新增紀錄。
- 系統資料庫卡片統一選單、按鈕與說明的內距。Hub 頁面依可用寬度調整欄數、導覽、表單和按鈕；不套用 Hub CSS 至 K7。

## 高頻監控

- 使用已儲存的 entity_id 在既有實體插孔清單中查找排插及插孔，而非邏輯設備原始 Slot。
- entity_id 不在已知清單時回報錯誤並停止高頻讀取，不猜測插孔。若日後在 HA 改 entity_id，必須同步更新清單。
- 實際讀取採用目標實體排插的輪詢頻率；設定儲存期間尚未完成的舊配對回應會被捨棄。
- 即時讀取及歷史補算共用同一個交易式事件處理器：一次高讀值開始、連續兩次低讀值結束。
- 原始採樣、事件及處理進度一起提交，重啟可續接事件；切換配對會結束舊配對事件。
- 維持原門檻（80–140 V 且電流至少 0.005 A 或功率至少 0.5 W），未重新校正門檻。既存已結束歷史不刪除、不重新分類；舊版錯計數不會在此更新中自動消失。
- 離線期間沒有採樣，不能推算其間實際運作次數。

## 驗證

- `go test ./...`、`go vet ./...`。
- 新增快照 WAL 完整性、種子刪除／交易、事件重啟／重播、跨排插配對、更新互斥及本機健康檢查測試。
- `tests/ui-reliability.cjs` 使用本機 fixture，不連接魚缸或 HA；測試首頁、系統、水質、電源、Thread、計算工具、滴定模擬頁在 320、390、768、1024、1366、1920 像素寬度。
- 瀏覽器測試需 Playwright。以 `NODE_PATH` 指向安裝位置；預設 Chromium，Windows 可用 `BROWSER_CHANNEL=msedge`。`UI_SCREENSHOT` 可指定資料庫卡片截圖輸出檔。
- 這些是本機測試，不等於全部實體手機或實機 OTA／斷電回滾驗收。
